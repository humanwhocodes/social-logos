# AGENTS.md

Guidance for coding agents working in this repository.

## What this is

`@humanwhocodes/social-logos` publishes 49 social media logos as standalone SVG
files and tree-shakeable React components. Both outputs are generated from one
vendored copy of the artwork, so a logo's geometry is never written down twice.

- Package license: **Apache-2.0**. Artwork license: **CC0-1.0**.
- ESM only. No runtime dependencies. React is an optional peer dependency.
- Node >= 20.

## The golden rule: most files here are generated

**Never hand-edit these.** They are rewritten by `npm run build` and your
changes will vanish:

| Path            | Generated by                            |
| --------------- | --------------------------------------- |
| `src/svg/`      | `scripts/generate.js`                   |
| `src/logos/`    | `scripts/generate.js`                   |
| `src/index.ts`  | `scripts/generate.js`                   |
| `LOGOS.md`      | `scripts/generate.js`                   |
| `dist/`         | `tsc`                                   |
| `vendor/logos/` | `scripts/update-vendor.js` (except pinned artwork) |
| `vendor/provenance.json` | `scripts/update-vendor.js`     |

To change a logo, change its **input**: `scripts/manifest.js` or the vendored
artwork. To change how components behave, edit `src/logo.tsx`, `src/types.ts`,
or the emitter in `scripts/generate.js`.

Hand-written source is only: `scripts/*.js`, `src/logo.tsx`, `src/types.ts`,
`tests/logos.test.js`, and the docs.

## Commands

```bash
npm run build          # generate, then compile with tsc
npm test               # builds first (pretest), then runs the suite
npm run update:vendor  # re-fetch artwork from the simple-icons devDependency
```

There is no lint step. `npm test` is the gate.

## How the build works

```
vendor/logos/<icon>.svg          committed artwork, the source of truth
  └── scripts/generate.js
        ├── src/svg/<slug>.svg   published under the /svg entrypoint
        └── src/logos/<slug>.tsx compiled into the main entrypoint
```

`scripts/manifest.js` is the control file: it lists every logo with its
`icon` (artwork file name), `collection`, `slug` (output file name),
`component` (export name), `label`, and official brand `url`. Nothing is
generated for artwork not listed there.

Each generated component contains only its own geometry and delegates to the
shared `<Logo>` wrapper in `src/logo.tsx` for sizing, color, and accessibility.
That one-module-per-logo layout is what makes the package tree-shakeable —
**don't consolidate components into a shared file or a lookup map.**

### Component contract

- `size` defaults to `"1em"`; sets both `width` and `height`.
- `fill` defaults to `"currentColor"`.
- `alt` sets `aria-label` with `role="img"`; omitting it marks the logo
  `aria-hidden` as decorative.
- Arbitrary `<svg>` props pass through and are applied **last**, so callers can
  always override the defaults.
- SVG **files** carry no `width`/`height` at all. Only components do.

### Artwork constraints

The generator enforces some of these and will fail the build:

- viewBox must be `0 0 24 24` (asserted by a test).
- No `fill` attribute on the geometry — it would defeat the `fill` prop.
- No background `<rect>`.
- Only `<path>`, `<circle>`, and `<g>` elements.

## Vendoring and pinned artwork

`scripts/update-vendor.js` runs in two phases: it resolves and validates
everything first, and only then writes. **Keep it that way.** Pinned artwork
cannot be re-fetched, so a partial failure must not touch `vendor/`.

Most logos are fetched from the `simple-icons` devDependency. A logo that
upstream removed — or that never existed there — is *pinned*: its file is
committed and its manifest entry carries an `artwork` block with `version`,
`source`, optional `license`, and a `sha256` checksum.

Version and license live **per entry, not per collection**, because logos are
removed upstream at different times and hand-vendored artwork can carry
different terms. Don't move them back onto the collection.

The checksum is the only guard on pinned artwork. Both the vendoring script and
the test suite verify it.

## Licensing rules (hard constraints)

1. Artwork must be under an **Apache-2.0-compatible** license. The test suite
   enforces an allowlist of `CC0-1.0` and `MIT`. Widening it is a deliberate
   licensing decision — not a way to make a failing test pass.
2. **No copyleft artwork, ever.** GPL or CC BY-SA would contaminate the package
   license. The project originally used Automattic's GPL sprite and was rebuilt
   specifically to escape it. Don't reintroduce it.
3. No license here grants rights to the **trademarks**. Never write docs
   implying otherwise. `NOTICE.md` and the README say this explicitly, and that
   wording is deliberate.
4. Adding a brand is also a judgment call. Amazon, CodePen, Eventbrite, and
   LinkedIn were all removed from simple-icons after the owners objected. If a
   brand has objected, raise it rather than adding it silently.

## Testing

`tests/logos.test.js` uses `node:test` and renders components with
`react-dom/server`. It covers exports, rendering, props, accessibility, the
generated SVG files, provenance, licensing, and pinned checksums.

When adding a logo, no test changes are needed — the suite derives its
expectations from `scripts/manifest.js`. If you find yourself hardcoding a logo
name or SVG string in a test, derive it from the manifest instead.

## Conventions

- Tabs for indentation, in every language.
- ESM everywhere. `scripts/` are ESM `.js` with JSDoc types; `src/` is
  TypeScript.
- JSDoc on exported functions, with `@param` and `@returns`.
- Comments explain *why*, not *what*. Match the existing density.
- Generated files start with `// Generated by scripts/generate.js. Do not edit.`

## Repository layout notes

Skills live in `.agents/skills/`. `.claude/skills` is a symlink to it, recorded
in git as mode `120000`. On Windows without Developer Mode the symlink cannot be
materialized; a directory junction stands in locally.

`vendor/` is committed — it is the artwork source of truth. `.gitattributes`
forces LF line endings because the pinned checksums are computed over
normalized content.

## Skills

Two skills document the recurring maintenance work. Prefer them over improvising:

- `update-social-logos` — refreshing artwork, bumping simple-icons, recovering
  from a logo removed upstream.
- `add-social-logo` — adding, replacing, or removing a brand, including logos
  simple-icons doesn't carry.
